# Auth, consent & trusts — the detail behind the AGENTS.md one-liners

Deep-dive: `docs/architecture/auth-and-consent.md`. Pinned by `repo_invariants/trust.rs`.

- **Auth: lazy, shared token refresh.** Refreshes ~60s before expiry behind a per-`(tenant, scope set)` lock; the access-token cache also keys on CAE-ness (Graph flows mint CAE — `is_graph_scope_set`); the `/token` POST rides `core::http_retry` (refresh grants idempotent, the auth code only on 429; a `Retry-After` over 30 s is terminal — the refresh lock is held across it); refresh tokens in the OS keyring, chunked (Windows Credential Manager caps at 2560 UTF-16 bytes — don't collapse the chunking), every chunk tagged with a per-write generation (`azapp2:{count}:{gen}:` on chunk 0, `{gen}:` after) so a torn set loads as no session, never a splice — `azapp1:` and unmarked entries still load; a write refused at chunk 0 keeps the previous set, and the silent refresh's write is best-effort (interactive flows still fail on it). The `/token` client follows no redirects and caps the body at 64 KiB; `expires_in` is capped at `MAX_TOKEN_TTL_SECS`. Write scopes consented **incrementally**. Access tokens live in memory only, zeroized on drop, `Debug` prints `<redacted>`.
- **Extra-scope tokens (on-demand).** Admin-consent/premium scopes ride a `ScopedTokenAdapter`, never the sign-in scope set. Every call must **degrade gracefully** (an `unavailable`/`consent_required` state, never a hard error).
- **Silent grants can't *obtain* consent.** AADSTS65001/65004 → `AuthError::ConsentRequired` (≠ `InvalidGrant`). `consent_required` crosses `BearerProvider` (`reauth::passthrough_code`), so the shared toast fallback fires anywhere; a command that has side effects before its scoped call, or needs a specific feature's "Grant consent" button, still **pre-acquires** via `AppState::ensure_*` so consent surfaces before any work. A missing consent must not purge the refresh token. `interaction_required`/`login_required` (CA step-up, incl. `invalid_grant` + AADSTS50074/50076/50079/50158) → `AuthError::InteractionRequired`, a non-fatal pass-through (never in `REAUTH_FATAL_CODES`), never purges; recovery `request_scope_step_up` → `step_up_where_required` (Graph features step up on the read scopes; non-Graph only when their silent acquisition still needs it) → `step_up_for_scopes` (`prompt=login`); a surface with its own error uses `VerifyIdentityButton`, never raw `e.message`.
- **Sign-in environment failures get their own surface.** Launch `restore_session` returns `Err` ONLY for `network` (refresh token intact → warning Callout + Retry via `views::sign_in::attempt_restore`); every other empty case stays `Ok(None)`. A browser that won't launch hands the authorize URL to `EntraAuthService::set_browser_fallback` (`Some(url)` then `None` when the flow ends) → `auth-browser-fallback` event → `BrowserFallbackNotice` in `Root` (`CopyBlock`); never log the URL. A credential store that can't be registered (Linux: no Secret Service) is `AuthError::KeyringUnavailable` → `keyring_unavailable`, distinct from a locked `keyring`.
- **Force re-auth in place when the session is dead — don't sign the user out.** A dead refresh token (`InvalidGrant`/`RefreshTokenMissing` → **`refresh_missing`**; `NotSignedIn` → **`not_signed_in`**) can't be re-minted silently; `reauthenticate` runs ONE interactive round trip and restores the session **without** dropping data caches. Only the `sign_in` command sweeps (`forget_tenant`, every token slot of the tenant, and a different previous account's keyring token).
- **Role/scope catalog.** Three auth planes (Entra, Azure RBAC, Exchange) share one capabilities catalog. Adding a privileged feature → add a catalog entry instead of hardcoding role strings; splice its remediation into a 403 via `graph_err::forbidden_remediation`. Access Readiness enumerates only **direct** Azure role assignments (conservative supersets, never a false "Missing").
- **SAML signing-cert rollover: phase derives from live SP state, not stored.** Entra auto-promotes a staged cert when the active expires. A cert **thumbprint is SHA-1**; `core::thumbprint::canonical` is its ONE converter — 40 hex chars are *also* valid base64, so never hand-roll the decode.
- **Auth trusts are validated wherever minted.** Federated credentials go through `core::federation` on **every** path (Graph accepts a bad issuer silently; the issuer's authority must be a bare `host[:port]` — no userinfo, backslash or whitespace, which hide the real host); every logout-URL write runs `core::redirect::validate_logout_url` (https only), not just the reply-URL check (pinned per function by `trust.rs::every_command_that_writes_a_logout_url_validates_it_first`); SAML cert lifetimes are bounded by `sso::resolve_cert_lifetime_days` on every mint (pinned per function by `repo_invariants/trust.rs`), and OIDC client secrets by `resolve_secret_lifetime_days`.
- **Errors are sanitized before they're shown or logged.** AAD errors are redacted to the AADSTS code; every client's error bodies (Graph, ARM, Key Vault, Exchange) are control-char-stripped and length-capped by `core::http_error::sanitize_error_body` — log the `ui_code`/status/request id, never a raw body.

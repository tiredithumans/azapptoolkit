# Backend, commands & caches — the detail behind the AGENTS.md one-liners

Deep-dive: `docs/architecture/caching-and-search.md`. Pinned by `apps/desktop/src-tauri/tests/repo_invariants/`.

- **Tauri commands:** `#[tauri::command] async fn` → `State<'_, AppState>` → `Result<T, UiError>`. Must be in `generate_handler![]` AND have a typed stub in `web-rs/src/bindings/` calling `invoke_result` from `bindings::ipc`, never `tauri_sys::core` directly (upstream unwraps a non-`UiError` rejection into a panic; the wrapper maps it to code `ipc`). Registry, binding literal, arg keys and return type are pinned by `repo_invariants/ipc.rs`. Frontend args use `#[serde(rename_all = "camelCase")]`; Rust params stay snake_case. `*_not_found` codes come only from `UiError::not_found("<resource>", …)` — never hand-spelled in `validation`/`new`, never a resource that already ends in `not_found` (pinned in `repo_invariants/commands.rs`). Common arg shapes (`TenantArg`, `ObjectIdArgs`, `AppIdArgs`, …) live in `bindings/common.rs`. `commands/` has domain subdirectories (`applications/`, `audit/`, `exchange/`, `permissions/`, `sso/`), each re-exporting flat so `commands::<domain>::name` paths never change.
- **Tenant-scoped caches — cross-tenant leakage is the #1 footgun.** Keys are `{tenant_id}|{kind}`, never unscoped; sign-out sweeps **every** kind and every per-tenant client map (`AppState::forget_tenant`), and so does the `sign_in` command (a different account on the same tenant) — never `reauthenticate`. Every pinned entry (the two indexes, both corpora, the three list caches, the credential roll-up) is typed — read through its `*_hit` accessor or `get_typed`, never `cache.get` (which misses and rescans; pinned by `pinned_keys_are_read_only_through_get_typed`); list commands return the cached `Arc`. Commands reading the `CacheKind::Audit` bucket (audit run, site/Key Vault sweeps, also typed) are `async fn → Result<Option<_>, UiError>`, never sync (`cached_scan_reads_are_async_commands`). A cache-**only** command must prove the session (a `graph_for` call is not a proof); never pin a per-object key. A full `/applications` list scan lives only in `scan_app_list` behind `app_scan_gate` (audit/bulk excepted; pinned in `repo_invariants/cache.rs`); per-list Refresh of an SP-index-derived list also drops `sp_index`.
- **Invalidate caches only on `Ok`.** SP/app-reg mutation → `invalidate_app_lists(...)`; **credential-only** → `invalidate_app_credentials(...)` (keeps the indexes); detail-affecting grant/revoke/scope/owner/remediation writes that can't change the app/SP set → `invalidate_app_detail_state` (details + audit run); `appRoles`/`oauth2PermissionScopes` and any in-place app PATCH (SSO URLs, redirect URIs, claims mapping) → `invalidate_app_details` only (pinned by `an_in_place_write_never_busts_the_list_tier`); exposed app-role writes also `invalidate_app_role_resources`; an Azure role assignment also `invalidate_kv_sweep`. **Patch tier:** a create, delete or rename that ends in a clean `Ok` holds the changed object, so it calls `record_created_apps` / `record_deleted_apps` / `record_renamed_app` instead of `invalidate_app_lists`. These rewrite the four scanned entries (`apps_pairing`, `app_name_index`, `credential_expirations`, `sp_index`) through `Cache::patch_typed_index` and drop the projections (`invalidate_app_list_projections`, pinned equal to the rest of the list tier). A partial failure (or a failed/lost bulk DELETE) still busts the list tier. Patches must be idempotent (upsert/remove/set by id), and a patch that can't apply drops its key; the credential roll-up follows the app list's verdict at `APPS_MAX`. The "only on `Ok`" rule's invalidator set is **derived from the source** (`repo_invariants/cache.rs::invalidators`: every non-command fn that drops or patches an entry, to a fixpoint), so the patch tier and every `invalidate_*` helper are covered the day they are written. A core that can fail after its first write returns the landed-write flags + `Option<UiError>` (`create_application_core`, `GrantRun`, `downgrade_application_permission_core`); the command busts on the flags, then returns the error. A pinned index takes `generation_for(kind, key)` **before** the fetch (an owned `IndexWatch`, per KEY, released on drop) and stores via `*_if_current`. So does a long scan's **unpinned** result (audit run, site/Key Vault sweep, SSO cert board, app-role resource directory, per-app detail and `mail_scopes|` verdicts): watch before the function's first await (right after `claim()`), store via `put_if_current` / `put_typed_if_current` — never a plain `put`, never pinned (pinned by `long_scan_results_store_through_the_guard`); the audit's `mail_scopes|audit|` key carries the run-start org-wide snapshot its verdict was reconciled against. `AppState::forget_tenant` also `cancel()`s every read-sweep flag (sign-out and sign-in, never `reauthenticate`).
- **`CacheKind::ServicePrincipal` self-invalidates in the graph client, not the command aggregators.** Keyed by `appId` but SP mutators take an SP *object* id, so they sweep the tenant prefix on `Ok`; `invalidate_app_lists` does **not** touch this kind. Every SP-affecting Graph write sweeps it — `delete_application` and `restore_deleted_item` included, since an app delete takes its SP and `restore_deleted_item` restores SPs too (`invalidate_principal_caches`: SPs, resource-SP definitions and grants) — pinned by `graph_client_sp_mutators_sweep_the_sp_cache`. Every Graph read-through captures `generation_for` before its fetch and stores via `put_if_current`, never a plain `put` after an await (`prewarm_sps` is the documented exception), pinned by `graph_client_read_throughs_store_through_a_watch`.
- **Long-running writes stop on Cancel AND on a dead session.** `claim()` a `CancelToken` once, before the first suspension point (a later claim discards a cancel issued during it); latch `dispatch::SessionDead`, break on both, flag the result incomplete. A **read** fan-out (sweeps, backup; the audit its own captured fatal error) returns the dead-session error rather than a partial result; a **mutating** one (bulk delete / grant / expired-secret sweep) returns what landed, with the dead-session failure carrying its wire code (`BulkError.code` / `BulkDeleteFailure.code`) so the bar prunes, offers Undo and prompts re-auth — an error there threw the landed writes away. Pinned per **call site** in `repo_invariants/{cancel,fanout}.rs`; `KNOWN_GAPS` stays empty. One flag per run kind, each with exactly one `cancel_*` command — a flag shared between kinds lets one Cancel stop both (pinned in `repo_invariants/cancel.rs`).
- **Batched Graph fan-out + adaptive throttle.** Heavy fan-outs use Graph JSON batching + the shared `ConcurrencyThrottle` via `FanOutMeter::attach` (`|| meter.limit()`; `ThrottleGuard::attach` only inside `throttle.rs`, pinned in `repo_invariants/fanout.rs`), degrading to per-object reads on a whole-batch failure. Never hand-roll a tracker or a per-item loop. `$expand` + advanced query fails *silently*.
- **Every paged read sends `$top`.** Paging is serial, so Graph's default of 100 is a 10× round-trip multiplier — paged reads (and `$batch` sub-URLs) send `client::MAX_PAGE_SIZE`, `/applications` sends `DEFAULT_APP_PAGE_SIZE`, or `Prefer: odata.maxpagesize` where `$top` is capped lower; pinned by `repo_invariants/fanout.rs::every_paged_graph_read_sends_a_page_size`, exemptions justified in its table. Every paging helper takes the consistency flag page 1 used — no default.
- **Full-collection PATCH for `appRoles` / `oauth2PermissionScopes`.** Graph **full-replaces** these not-nullable arrays — re-read live state, mutate, write the whole array back (never merge a cached payload). Deleting an enabled entry needs two PATCHes: disable, then remove. Exposed **app roles** edit the **paired application** when one exists (else the SP) and round-trip as **raw JSON** so the `value: null` SAML default survives byte-for-byte.
- **camelCase vs snake_case.** Graph domain models (`Application`, `ServicePrincipal`) are camel (no serde rename); DTOs/bindings are snake_case. `Application` + `AuditItem` cross IPC **as-is** — renaming a field is a wire-format change.
- **One definition per policy.** The Graph/ARM/Key Vault error taxonomy comes from `core::http_error_enum!`; `ExchangeError` is hand-written because its `Forbidden { detail, had_diagnostics }` is a struct variant the macro cannot express, and `azapptoolkit-exchange/tests/error_conformance.rs` pins its `ui_code`/`is_retryable`/Display to an instance of the macro. Retry budget + backoff from `core::http_retry` (`RetryBudget`, `with_retries`) — including `$batch` (inner 429/5xx sub-requests re-batched like the GET alone) and the scoped (explicit-token) writes; only the one-shot `scoped_get` skips it. Every transport, Exchange included, derives its `RetryClass` via a `retry_class_for` helper (Exchange from the cmdlet verb, since every cmdlet is a POST); naming `MAX_RETRIES`, `next_backoff_ms`, `sleep_before_retry` (or the other schedule primitives) outside `http_retry.rs` fails `repo_invariants/trust.rs`. Every `reqwest::Client::builder()` sets `.connect_timeout(core::http_retry::CONNECT_TIMEOUT)` and `.expect`s its build — never `unwrap_or_default()` or a bare `Client::new()` (pinned by `trust.rs::every_http_client_has_a_connect_budget`). ARM and Key Vault map status→variant through `core::http_error::failed_response` (the macro emits `HttpStatusError`); Graph keeps its own for the CAE re-mint and throttle observer. Error bodies go through `core::http_error::sanitize_error_body`, network errors through `describe_error_chain`, and the throttled wait through `ThrottleWait`. A client supplies only what is genuinely its own (`ui_hint`, extra variants). Re-auth-fatal codes have ONE definition: `core::reauth::REAUTH_FATAL_CODES` — `UiError`/`TokenError::is_reauth_fatal()` both read it (agreement tested in `azapptoolkit-dto`); adding a code = editing that slice, and every long-running loop stops on it.
- **The `BearerProvider` boundary carries the auth classification.** `core::token::TokenError { code, message }` — not a bare `String` — so a dead session survives into `GraphError/ExchangeError/KeyVaultError/ArmError::Token` and `ui_code()` passes every classified code through via `core::reauth::passthrough_code` — the fatal `REAUTH_FATAL_CODES` plus the disjoint, non-fatal `PASSTHROUGH_NON_FATAL_CODES` (`consent_required`, `network_error`). Flattening it to `token_error` made `is_reauth_fatal` unfirable for every client call. Sole mapping: `token_adapter::token_error`.
- **Per-tenant operator defaults live in `settings.json` too.** `UserSettings.tenant_defaults` (types in `azapptoolkit-core::defaults`, ungated — also the IPC payload). **Every writer goes through `UserSettings::mutate`** — `commands::config`, `commands::defaults`, the Key Vault rotation's vault binding (`commands::keyvault`) and the remembered account (`AppState::remember_account`/`forget_account`). It serialises under a process `Mutex` plus an OS `File::lock` on `settings.lock` (a second app instance), and **refuses** rather than overwrites a settings.json that exists but can't be read or parsed. `stored`/`load` are the lenient read-only paths; `save_locked` is private, the only serializer. `apply_tenant_defaults` writes only operator-editable fields and **preserves `default_vault`/`app_vaults`** (owned by the rotation flow); it destructures `TenantDefaults` exhaustively, so a new field won't compile until it's decided there.
- **Build-time config baking.** `build.rs` reads `.env` → `AZAPPTOOLKIT_BUILD_*`; env vars override. Only public-client identifiers — never a credential.
- **CSP governs the *webview*, not backend egress.** `connect-src` in `tauri.conf.json` is `'self'` only — the WASM frontend has no HTTP client, and every Graph/login/Key Vault/ARM/Exchange call is backend reqwest, which needs no CSP change. `repo_invariants/webview.rs` pins it (and the capability file to `core:default`); a webview-side fetch would have to add its origin in both places.
- **Permission definitions resolve live, never from a bundle.** `azapptoolkit-permissions/data/catalog.json` is only a resource *directory* (well-known first-party `appId` + name) that seeds the picker dropdown and the Permissions tab's resource names. Every app role and scope, for directory and tenant resources alike, comes from `resolve_resource_sp()`, cached under `CacheKind::Permissions`. The resolution ladder is live SP → raw GUID with the declared kind. With Graph unreachable, the picker lists names with no permissions; there is no stale fallback, by design.
- **Audit signals — structured, not text.** Facets/cards/finding groups key off `AuditItem` fields, not free-text. A `cancelled`/`truncated`/`degraded` run is **never cached** nor shown as an all-clear; a backup records what it missed in `TenantBackup::skipped`.
- **Bulk remediations reuse the single-app cores, sequentially** via `run_bulk_seq` — **not** `dispatch_capped` (those cores take `State`, not `Send`). They `claim()` a `bulk_cancel` token, degrade to a per-app structured `BulkError`, and stop on a re-auth-fatal code. SP-only audit rows (`AuditItem.principal_kind`) call the SP-only cores, **never** `remediate_scope_*` (which `get_application` first → 404).

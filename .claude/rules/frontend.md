# Frontend (Leptos/WASM) — the detail behind the AGENTS.md one-liners

Deep-dive: `docs/architecture/frontend-workspace.md` (sharding + the `strip`/`reset()` footguns included).

- **Reactivity is closure-based.** `{move || sig.get()}` for tracking; `.get()`/`.with()` to read. State is `RwSignal<T>` on a context-provided `Session`. CSS: plain global `styles.css` with BEM-ish names; every class selector must be rendered in `src/` (or be a `thaw-*` override / `format!("{base}--{…}")` modifier) and every `var(--token)` declared (pinned by `tests/stylesheet_coverage.rs`). Global keys live in `hooks::use_shortcuts`; a **bare-key** binding MUST no-op in a text field or it eats typing (`hooks::is_text_entry`, the one predicate shared with the grid hook — a focused checkbox is not typing) and while a modal is open (`hooks::modal_is_open`). A `role="menu"` panel MUST wire `hooks::use_menu_keynav`. A true/false ARIA state (`aria-expanded`/`-selected`/`-pressed`/…) is bound to a *string* (`.to_string()`), never a bare `bool` (pinned by `tests/aria_state_bindings.rs`).
- **A command's result can land after its component is gone** (sign-out unmounts the shell; closing a pane disposes its tabs). After an await: if `Session::is_active_tenant(started_for)` is false, land nothing (a toast would carry into the next sign-in); on the same tenant, skip component-local writes once disposed but keep session-level effects; call a `Callback` with `try_run` and read a signal with its `try_` twin — a plain `get`/`with` panics once disposed, and an `is_disposed()` return does not excuse one (the pin is textual). `CommandState::land` does it for every `use_command` runner, the bulk bar's `Landing` for its runs; a hand-spawned task's post-await `.run(` or `.get(`/`.with(` fails `tests/post_await_callbacks.rs`. A consent-then-replay (`do_run()` after the consent await) reads signals indirectly, so it is gated on `is_disposed()` + `is_active_tenant` by hand — at the call site, or at the top of the replay itself (`ScopeWizard::run_apply`, `SsoWizard::run_create`), which every caller then inherits.
- **One primitive per UI pattern (design-consistency invariant).** Page header = `components::ui::SectionHeader`; loading = skeletons (`SkeletonList`/`DetailSkeleton`/`SkeletonCard`, each a `role="status"` region), spinners only in-button/inline; load failure = `DetailLoadError`; inline action error = `FormError`; notices/alerts = `components::ui::Callout`; windowed-list footer = `components::ui::ShowMore`; status pill = `Badge` (`BadgeTone`); table = `DataTable` (or `use_grid_keynav` for a keyed `<For>`); tabs = `TabBar` with a required `label` and an opt-in `panel_id` (`tab_id` for the panel's `aria-labelledby`); filter box = `SearchInput` (named by a hidden label); dialog = `components::modal_shell::ModalShell` (backdrop, `role="dialog"`, a per-instance title id, focus trap, Escape gated on `busy` and the reactive `close_on_escape`) — a dialog passes only its content as children. Reuse the primitive; don't re-implement the markup (repo_invariants tests scan for hand-rolled callouts, badges, raw form-errors and unwired tables; `web-rs/tests/dialogs_use_modal_shell.rs` fails on `role="dialog"`/`"alertdialog"`, `aria-modal`, a `modal-backdrop` class or a thaw `Dialog` anywhere in `src/` but `modal_shell.rs`).
- **Open-items workspace = full-width lists + ONE shared cross-entity working set.** `session.open_item(kind, entity_id, title)` fills `Session.open_items`; no side detail pane, and the dock + workspace mount **once in `shell.rs`**. **Footgun:** `open_items` + `shown_items` MUST reset in `set_active_tenant`, or a stale item leaks the prior tenant's data. The set is parked per tenant (`azapptoolkit:workspace:{tenant}`); `update_open_items` is the sole writer. No `selected_*_id` signals.
- **Per-list filter state lives on `Session.tenant_ui` (`TenantScopedUi`) and resets on tenant switch by structure.** A new tenant-scoped signal goes INTO the substruct with a `reset()` line + an assertion in the `tenant_switch_resets_every_tenant_scoped_field` pinning test — never a bare `Session` field with a hand-added reset.
- **Bindings mirror commands.** The command-name string is the flat snake_case fn name; args structs are snake_case Rust with `#[serde(rename_all = "camelCase")]`; reuse the shapes in `bindings/common.rs`; use `bindings::ipc::invoke_result` for `Result<T, UiError>` commands — never `tauri_sys::core` directly, whose `invoke_result` panics on a rejection that is not a `UiError` (pinned by `repo_invariants/ipc.rs`, with the arg keys and return types). `Application` + `AuditItem` cross IPC as-is.
- **WASM gating.** `web-rs` compiles to `wasm32-unknown-unknown`. Server deps (tokio, reqwest, rustls) must be gated `#[cfg(not(target_arch = "wasm32"))]` in shared crates, or excluded from `web-rs`. `web-rs` is outside the workspace, so it declares its own `[lints.rust] unsafe_code = "deny"` — keep it in sync with the root block (pinned by test).
- **GitHub Pages demo = the WASM frontend with the Tauri backend mocked.** `just web-build-pages` builds with the `demo` feature (off in `web-build`/desktop, so the mock never ships). **Footgun:** any infallible `invoke()` must be in `demo::register_fixtures` or it **panics the whole page** — enforced by `web-rs/tests/demo_fixture_coverage.rs`, which also requires every read to be fixtured (or allowlisted with a reason) and every fixture to name a bound command; demo rows are built from the demo's own catalog and dated relative to today (`demo::tests`, run by `just web-test`).
- **Auto-update is interactive (not silent).** The front-end checks once on launch and toasts a notification whose action opens `UpdateSplash` (explicit **Update & restart**). **Don't reintroduce a silent background `download_and_install` in `lib.rs` setup** — it would race the prompt.
- **Browser GUI tests are sharded** (`tests/gui_N.rs`, `#[path] mod` per module) to keep each served wasm under the ceiling headless Chrome will instantiate and give each binary its own 60 s runner budget; `just web-itest-size` enforces the per-shard ceiling. Renaming a CSS class / aria-label / on-screen text a test references fails CI — the `web-test-strings-check.sh` hook flags it at edit time.

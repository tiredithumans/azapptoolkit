## How to read this report

The review ran 26 first-pass slices that together covered every source, documentation and CI file in the repository, then a completeness critic named six lenses the slices had not applied and six gap slices swept those. Every finding cites a `file:line` with quoted evidence. Every finding was adversarially verified by an independent agent that re-read the code, and the high-severity bug and security items were re-verified a second time. Two judges then ranked the survivors, one for operator risk and value, one for engineering leverage, and the lead session spot-checked 12 of the 14 high items directly in the code (see Appendix C and the self-verified notes). Environment limits: the desktop (Tauri) crate could not be compiled in the review container because WebKitGTK is absent, so its roughly 300 inline tests were reviewed statically; the shared crates' tests (591), the frontend host tests (200) and the wasm type-check all pass. Verdict legend: **confirmed** means the claim holds as stated; **partially** means the claim is true but overstated or mis-cited, and the entry carries the verifier's correction on its verdict line. ## Executive summary

azapptoolkit is a mature, unusually well-documented codebase with an explicit safety contract (never under-report, never cache a degraded run, coverage is never overstated, a partial success is a real write) and a source-scanning invariants suite that pins many of those rules. Its strengths are real and consistent across slices: the pure decision cores (Exchange `verdict`/`targets`/`aap`, the LRU+TTL cache with its store-after-invalidate guard, the resource-aware scoping gates, the audit scorer) are fail-closed by construction and heavily table-tested; the Graph transport has one retrying core with verb-derived retry classes and same-origin guards; auth hardening (PKCE, state, nonce, tid/oid re-binding, chunked keyring, AADSTS redaction) is careful; IPC parity is exact at 186 commands; and the frontend has a single-writer open-items design, strong a11y foundations and a well-reasoned GUI harness. The dominant problem is results that mislead in the reassuring direction: a whole family of RBAC-scopable mailbox permissions scores as healthy, the 5000-site sweep and a swallowed SP lookup are cached as complete, backup Pass 3 thins silently, partial AAP migrations and vetoed one-click fixes toast success, and a restore that duplicates the estate is offered on screen as the re-run remedy. Second come documented controls that do nothing: the auto-update opt-out is never read, the install format is never checked, and the Linux artifact cannot start on Ubuntu 22.04, Debian 12 or RHEL 9. Third are session and auth edges: a domain-form tenant id the config screen accepts can never sign in, `interaction_required` purges the whole session, sign-out fails open on a keyring error, and CAE-ness is missing from the token cache key. Fourth are engineering-debt clusters: three cancel flags shared across run kinds that the keep-alive UI lets overlap, frontend primitives bypassed at dozens of sites, invariant rules that pass vacuously, the Exchange transport outside the shared retry class and error taxonomy, and an orchestration layer with almost no handler-level tests. Finally, several load-bearing sentences in AGENTS.md and `docs/architecture/` now instruct contributors to do the wrong thing. Almost every fix has a precedent in the same file or a sibling module, and roughly half of the top items are small. Verification was strict: 131 claims were narrowed with a recorded correction and one was refuted. Start with the mailbox scoping tables and the dropped coverage signals (F151, F178, F023, F039), then the updater gate and the Linux runner pin, then the shared cancel flags.

## Top priorities

Items 1 to 5 were ranked by both judges; items 6 to 12 alternate the operator-risk and engineering-leverage lenses.

**1. Tenant-wide mailbox permissions invisible to the audit, and the EWS scope never gets a verdict** (F151, F251, F054) · high · S for the tables, M for the resolver. Both judges ranked this. `mailbox_named` at `crates/azapptoolkit-core/src/scoping.rs:195` covers only `Mail.`, `MailboxSettings.`, `Calendars.` and `Contacts.`, so an app holding `Mail-Advanced.ReadWrite.All` or `MailboxItem.ImportExport.All` gets a healthy row, no Scope fix and no high-risk points; this is the exact class the audit exists to catch. In parallel, `resolve_mail_scopes` at `apps/desktop/src-tauri/src/commands/exchange/mail_scopes.rs:108` hardcodes the Microsoft Graph resource, so EWS `full_access_as_app` shows Unknown forever and a correctly RBAC-scoped EWS app still scores org-wide. Start by extending `mailbox_named` with the `MailboxItem.`/`MailboxFolder.`/`MailboxConfigItem.`/`Mail-Advanced.` prefixes plus entries in `HIGH_RISK_APP_PERMISSIONS` at `crates/azapptoolkit-core/src/audit/permissions.rs:67`, with a table test citing Microsoft's RBAC-for-Applications roles; then make the resolver accept `(resource, value)` pairs and add the joined resolver test that F456 names at `apps/desktop/src-tauri/src/commands/exchange/tests.rs:200`.

**2. Capped and degraded reads drop their signal and are cached as complete** (F178, F059, F452, F023, F002, F039, F040) · high · M. Both judges ranked this. `list_all_sites` at `crates/azapptoolkit-graph/src/client/sharepoint.rs:105` truncates at 5000 sites and returns no flag, so `is_complete()` is true, the per-app panel says the app reaches no site, and the result is cached for 60 minutes; `score_one` at `apps/desktop/src-tauri/src/commands/audit.rs:1489` swallows a failed SP lookup and the run caches as a clean scan; `permissions_resolve.rs:277` caches a degraded detail that shows granted permissions as not granted; backup Pass 3 at `apps/desktop/src-tauri/src/commands/backup.rs:675` has no session latch and records nothing in `skipped`. The fix shape already exists in each file: return `(rows, truncated)` as `collect_all_pages_capped` does and fold it into `is_complete()` (the DTO at `crates/azapptoolkit-dto/src/sharepoint.rs:130` needs a serde-defaulted `truncated`), return `Err` instead of `None` so the existing Transient classification marks the run degraded, skip the cache put on a degraded resolution, and thread `SessionDead` plus `note_graph_failures` into Pass 3 as Passes 1 and 2 already do.

**3. The documented update opt-out is inert, MSI and .deb installs get the wrong payload, and Linux builds cannot start on current LTS distros** (F036, F139, F487, F488) · high · S. Both judges ranked this. `UserSettings::load`, the only reader of `AZAPPTOOLKIT_AUTO_UPDATE`, has no production caller, so every launch egresses to GitHub against the README's MDM promise; `check_for_update` at `apps/desktop/src-tauri/src/commands/updater.rs:26` never consults `tauri::utils::platform::bundle_type()`, so an MSI operator who clicks Update gets a second per-user NSIS install and a .deb install downloads the AppImage and fails with a raw plugin string. The Linux release leg at `.github/workflows/release.yml:105` runs on floating `ubuntu-latest`, so the AppImage and .deb import `GLIBC_2.38` and fail at exec on Ubuntu 22.04, Debian 12 and RHEL 9. Add a pure `update_policy(auto_update, bundle_type)` function with a unit test, make the DTO tri-state so `shell.rs` can hide or relabel the menu item, pin the Linux runner to `ubuntu-22.04` and add an `objdump -T` guard step that fails when the max `GLIBC_` version exceeds 2.35.

**4. One Cancel button stops every long run of every kind, and concurrent fan-outs clobber each other's throttle** (F440, F441, F442, F443, F444) · medium · M. Both judges ranked this. `audit_cancel` is claimed by the read-only audit, all 11 `bulk_*` writes and the AAP migration; `sweep_cancel` by the site, Key Vault and mailbox sweeps; `dr_cancel` by backup and restore. Every top-level view is keep-alive and `CancelFlag::cancel` stamps every older generation, so the docstring at `apps/desktop/src-tauri/src/commands/bulk.rs:127` ("never run at once") is a false premise and cancelling a scan can halt a bulk delete mid-selection. `GraphClient` has a single `throttle_observer` slot (`apps/desktop/src-tauri/src/commands/throttle.rs:141`), so whichever run drops first clears the survivor's adaptive back-off. Add `bulk_cancel` and `migration_cancel` to `AppState`, split `sweep_cancel` at `apps/desktop/src-tauri/src/commands/permission_tester.rs:443`, pin command-to-flag in `repo_invariants/cancel.rs`, and make `clear_throttle_observer` compare-and-clear; every frontend Cancel handler must then call its own command.

**5. The Exchange transport sits outside the shared retry class and error taxonomy, and the invariant that should catch it passes vacuously** (F140, F164, F166, F167, F168, F215) · medium · M. Both judges ranked this. `send_core` at `crates/azapptoolkit-exchange/src/client/transport.rs:265` open-codes its retry loop, so a `New-ManagementRoleAssignment` that committed before a 502 is replayed, fails as a duplicate and `grants.rs` then keeps the org-wide grant with "scoping is NOT effective"; `repo_invariants/trust.rs:163` skips any file without `with_retries(`. The verifier refuted the earlier "duplicate assignment survives removal" headline, so the accurate framing is false failures, not duplicates. Two smaller siblings ride along: `rbac.rs:220` lists references through `invoke_optional`, so a misclassified 400 can unlock an irreversible group delete, and `targets.rs:716` compares DNs case-sensitively while the post-write proof folds case. Port `send_core` onto `with_retries` with a `retry_class_for(cmdlet)` helper, make the trust rule fail any crate that references `MAX_RETRIES` or `next_backoff_ms` directly, and add an Exchange `error_conformance.rs` mirroring ARM's.

**6. Restore is not idempotent while the DR view and the restore report both tell the operator to re-run it** (F424, F037, F038) · high · M. Operator-risk lens. In the one scenario DR exists for, following the on-screen remedy at `apps/desktop/web-rs/src/views/dr.rs:502` ("recreates only what is missing") creates a second copy of every already-restored app with new appIds, paired SPs, fresh 180-day secrets and re-granted admin consent, and the Restore button stays live after a successful run. `restore.rs:751` repeats the re-run instruction and `restore.rs:734` reports failed Graph reads as runbook facts. Reword the callout and clear the loaded plan after `report.set`, stop the report saying "re-run the restore", then make Pass 1 (`restore.rs:197`) adoption-aware by display name plus a source marker.

**7. Give the orchestration layer a test seam** (F459, F457, F455, F010, F451, F450) · medium · M. Engineering-leverage lens. Roughly twenty confirmed bugs (F001, F004, F023, F037, F038, F039, F054, F070 to F075, F460) live in `State`- or `AppHandle`-bound bodies that no test can construct; only `credentials.rs` and `backup.rs` have wiremock handler tests, and `bulk.rs` proved the `ProgressSink` seam works then kept it private. Lift the trait from `bulk.rs:46` into `apps/desktop/src-tauri/src/commands/progress.rs:21` as `pub(crate)` with a test `Recorder`, replace the closure at `backup.rs:364`, add `commands/test_support.rs` with one mock base-URL convention and shared builders, then write the three F455 tests against `permissions.rs:618` and `permissions.rs:389`, which already take `&GraphClient` and need no refactor.

**8. The SSO claims editor detaches a live policy from an empty editor and writes transformation claims that can never be emitted** (F371, F071, F070, F447) · high · M. Operator-risk lens. A first-time operator without `Policy.ReadWrite` consent has the claims read swallowed to `None` at `apps/desktop/src-tauri/src/commands/sso/mod.rs:510`, the tab at `sso_tab.rs:543` renders an empty editor, and one Save detaches the configured policy; each save also orphans a tenant-level `claimsMappingPolicy` because `set_claims_mapping` (`mod.rs:1643`) unassigns and recreates instead of PATCHing. The codec at `sso/claims.rs:48` emits `TransformationID` instead of `ID` and conflates both on read, and the round-trip test at `claims.rs:442` pins the wrong shape. Add a `claims_read_failed` discriminator to `SsoConfigDto`, disable Save until a successful read with a Load-claims consent button, add `transformation_id` to the schema entry DTO, and replace the masking test with Microsoft's documented fixture.

**9. Pin the IPC contract mechanically and stop a non-UiError rejection from aborting the WASM app** (F088, F425, F019, F091, F368) · medium · M. Engineering-leverage lens. Command, arg-struct and return-type parity is exact today (186 = 186 = 186) but is checked only by `.claude/hooks/command-parity-check.sh:15`, an advisory hook that always exits 0 and needs jq; `invoke_result` at `apps/desktop/web-rs/src/bindings/mod.rs:17` unwraps the error deserialization, so any string rejection (invalid args, ACL) panics the whole frontend. Add `repo_invariants/ipc.rs` reusing `sources::commands()` with a vacuity floor, wrap `invoke_result` to deserialize through `serde_json::Value` and map a non-UiError rejection to `UiError::new("ipc", ..)`, and move `DirectoryIndexStatus` (`apps/desktop/src-tauri/src/commands/applications/mod.rs:86`) into the DTO crate.

**10. Audit-surface fixes report success while doing nothing or dropping warnings** (F394, F022, F403, F333) · high · S. Operator-risk lens. The Permissions-tab AAP migration gate at `apps/desktop/web-rs/src/components/exchange_scoping_section.rs:324` checks only `failures`, so a `partial` report (legacy policy kept, fail-closed) toasts "Migrated" while the sibling audit dialog gates correctly; the redundant-permissions Fix at `apps/desktop/src-tauri/src/commands/remediation.rs:257` returns empty `removed` and `skipped` when every value is vetoed and the UI hides the button; `scope_remediation.rs:111` hard-codes zero warnings so "groups were NOT applied" reads as clean; `permissions_tab.rs:116` sets its outcome note right before `on_changed` unmounts it. Add `AapMigrationReport::is_clean()` on the DTO (`crates/azapptoolkit-dto/src/exchange.rs:174`) and use it on both surfaces, push vetoed values into `skipped`, gate `on_done` on a non-empty `removed`, read `res.warnings.len()`, and toast failures before `on_changed`.

**11. Error codes are produced consistently but consumed inconsistently** (F110, F122, F462, F466, F467, F353, F465) · medium · S. Engineering-leverage lens. `consent_required` is flattened to `token_error` inside every client call (`crates/azapptoolkit-core/src/http_error.rs:129`), so the shared consent fallback never fires for scoped calls; the throttled message at `http_error.rs:76` reads "retry after Some(30)s"; `.toast__message` at `apps/desktop/web-rs/styles.css:3513` collapses the appended hint; only Graph has a connect timeout, so ARM, Key Vault and Exchange spin about four minutes against a firewalled host (`crates/azapptoolkit-arm/src/client.rs:38`); the inline-error path at `apps/desktop/web-rs/src/hooks/use_command.rs:85` (24 call sites) never offers Re-authenticate; and a 401 renders as bare text with hints that say "sign out" against the in-place re-auth design. Each is a one-file change on a shared producer or sink and reaches every surface at once.

**12. The permission tester reports a definitive no_access when its reads failed, and never sees EWS-only holders** (F055, F056, F057, F449, F058) · medium · M. Operator-risk lens. `orgwide_mailbox_grant` at `apps/desktop/src-tauri/src/commands/permission_tester.rs:63` folds a failed Graph read into `EntraReach::NotHeld`; `test_site_access` at `:1092` prints "holds no organization-wide SharePoint grant" when the grants read failed; `find_mailbox_reachers` at `:466` discovers candidates from the Graph resource only, so a principal with `full_access_as_app` over every mailbox is reported as no_access. An admin uses these answers to decide who can read a mailbox. Return a tri-state (Held / None / Unreadable), score Unreadable as unknown in `synthesize`, page `appRoleAssignedTo` on both mailbox resources, and let `exchange_available` reflect the real degraded mode so the documented partial-coverage caveat can fire.

## Strategic projects

- **Posture snapshot and drift report (#109)** (F267). Every seam the owner's design names exists and is unblocked; the project turns the audit from a point-in-time screen into "N new high-risk grants since the last snapshot", the question a security committee actually asks. Effort L, no new scopes or persistence policy.
- **Audit signal expansion** (F278, F161, F264, F276, F268, F078, F259, F274). The workbench never reads federated identity credentials (the class `federation.rs` calls the worst case), `disabledByMicrosoftStatus`, Identity Protection risk detections, workload-identity Conditional Access or per-credential sign-in activity. Each is one `$select` field or one v1.0 read plus a table-tested rule; together they change what the audit can claim.
- **Idempotent, destination-aware DR restore** (F424, F037, F042, F428, F090, F152, F150, F038). Resolve each manifest app in the destination before creating it, make `plan_restore` look at the destination and the schema, rewrite every `api://` identifier-URI form, model flexible FICs, and thread read failures into `ManualItem` reasons. This is the project that makes DR trustworthy rather than one-shot.
- **Run identity for cancellation, progress and throttling** (F440, F441, F442, F443, F444, F035). Beyond the per-kind flags in priority 4, have `claim()` return a generation that rides the first progress event as `run_id`, add a `cancel_run(run_id)` command, filter listeners by run id, and give the throttle a multi-observer slot. That also fixes interleaved bulk-progress rows across mounted `BulkActionBar`s and gives the AAP migration a real Cancel.
- **Detail-pane and launch-time state architecture** (F336, F357, F372, F471, F472, F333, F340). Every mutation rebuilds the whole detail pane and remounts every visited tab, which is the root cause of the deferred-reload workarounds, the torn-down certificate reveal, lost scroll and stale-snapshot replays; at launch every restored dock pane fires its full detail fetch hidden and Home ships the whole audit run over IPC for a few counts. A long-lived `RwSignal<Arc<ApplicationDetail>>` outside the Suspend, first-show gating of restored panes and a `get_cached_audit_summary` command form one coherent project.
- **Behavioural GUI coverage of the mutation-heavy surfaces and degraded audit states** (F343, F410, F430, F411, F400, F329, F414). The browser tests are the frontend's only behavioural gate, yet Owners, Expose an API, Permissions actions, rotate and federated flows, the SSO wizard, create app and enterprise Access have zero coverage, no test renders a cancelled or truncated run or asserts an ARIA state value, and 13 demo reads are unregistered. A shared helper module plus one shard per surface would have caught F333, F340, F371, F372 and F394 before shipping.
- **Capabilities catalog completion, with readiness derived from it** (F258, F021, F024, F163, F255, F391, F233, F262, F271). Readiness cannot recognise the custom Entra role the repo itself recommends, keeps a hand-maintained CAE list that has drifted, and has no entries for claims mapping or provisioning, so those 403s carry no remediation and the provisioning pane cannot offer consent. Adding the entries and deriving the probe list from the catalog restores the one-definition rule across the three auth planes.
- **One HTTP transport core and an observability baseline** (F166, F201, F467, F463, F290, F476, F479, F480, F481, F482, F478, F477, F484, F485). ARM and Key Vault duplicate the status-to-variant closure, Exchange keeps a hand-rolled enum, only Graph has a connect timeout, error bodies flow raw and network errors drop their cause; no client sends a `client-request-id` or captures `request-id`, write commands log no failures, webview panics never reach the backend log, and there is no "Open log folder" or diagnostics bundle. A `core::http_client` builder, a shared transport generic over the macro-generated error enums, one `warn!` hook at the UiError boundary and a small diagnostics command remove four copies of every future policy change and make failures diagnosable.

## Scorecard by area

### Shared crates (114 findings, 8 slices)

The pure decision cores are the strongest code in the repository: the Exchange `targets`/`verdict`/`aap`/`references` modules are fail-closed by construction with every past regression pinned by a named test, the core cache's store-after-invalidate guard is exhaustively tested, the scoping gates and Selected-scope levels match Microsoft's model, the federation and redirect validators close real userinfo-host tricks, and every role GUID in the capabilities catalog is correct. The Graph transport has one retrying core with verb-derived retry classes, a same-origin guard on every `nextLink`, and tenant-prefixed self-invalidating caches. The weaknesses sit where Microsoft moved after the code was written or where one path escaped the shared rule: the mailbox advisory misses the RBAC-era permission families, the flexible-FIC model cannot deserialize a null subject, `list_all_sites` is the one capped scan without a truncation flag, the Exchange transport open-codes its retry loop and error enum, the ARM `atScope()` semantics label inherited assignments as direct, and Log Analytics accepts a `PartialError` 200 as complete. Auth is careful about PKCE, nonce and keyring handling but treats `interaction_required` as a dead refresh token, omits CAE-ness from the cache key, and accepts a domain-form tenant id it can never sign in with. All 591 tests pass and the crate-level conformance tests exist for ARM and Key Vault but not for Graph or Exchange.

### Tauri backend (104 findings, 6 slices, plus most of the 52 gap-slice findings)

The command layer implements its documented contracts faithfully where they are pinned: tenant-scoped keys, tiered invalidation, generation watches on the pinned indexes, the full-collection PATCH contract, `run_is_cacheable`, `run_bulk_seq`, generation-based cancellation, atomic owner-only file writes, and exact IPC parity across 186 commands. The invariants suite derives its subjects from a source walk with vacuity floors and self-tests. The weak spots are the paths those pins do not reach: three shared cores return `Err` after a real Graph write so invalidation is skipped, degraded resolutions and swallowed SP lookups are cached, backup Pass 3 lacks the latch its siblings have, the restore is not idempotent while telling the operator to re-run, the claims codec mis-models Graph's schema entry, the permission tester and site sweep report unreadable or truncated data as clean, and the resolver hardcodes the Graph resource. Cross-cutting: three cancel flags and one throttle observer are shared across run kinds, only Graph has a connect timeout, no client sends a `client-request-id`, write commands log no failures, and handler-level tests exist only in `credentials.rs` and `backup.rs`. Three files (`audit.rs`, `permissions.rs`, `sso/mod.rs`) exceed 1400 lines and split along seams the repo has already used twice.

### Leptos frontend (128 findings, 7 slices)

Structure is sound: `TenantScopedUi::reset()` covers every field and is pinned, the open-items workspace has one write path with cross-tenant persistence tested, the error sink is coherent, every dialog wires a focus trap and Escape, `TabBar` implements the full WAI-ARIA tabs pattern, colour tokens clear WCAG AA, and the GUI harness (orphan-mount sweep, loud-reject unmocked policy, typed fixtures) is well reasoned. The recurring weakness is drift from the documented primitives: `Badge` is bypassed at 45 sites, 11 raw tables lack `DataTable` keynav, about 10 load failures skip `DetailLoadError`, both Owners tabs hand-roll `DirectorySearch` and reintroduce the "No matches under an untouched box" bug, and 66 form-error sites have no live role. Behavioural gaps follow the same shape: the SSO tab renders an unreadable policy as empty and Save detaches it, partial AAP migrations toast success, the whole detail pane remounts on every mutation, `invoke_result` panics on a non-UiError rejection, and the Key Vault browser survives a tenant switch. 125 of 186 command literals are never referenced by a GUI test and the untested set is exactly the mutation-heavy surfaces; the demo's ids and dates have drifted from its own catalog.

### Cross-cutting: tooling, docs, security, dependencies, API currency, product (92 findings, 6 slices)

Tooling is well reasoned and its rationales are pinned by tests, the security posture of the app's own code is strong (loopback PKCE with state and nonce, redacted `Debug` on secret types, `same_origin` on every follow, consistent OData and OPATH escaping, CSV and HTML escaping in exports, SHA-pinned actions, cargo-deny and cargo-audit on both lockfiles), dependency holds are still valid against today's registry, and every Graph call is on v1.0 except the one beta-only report. The edges are sharp: `just setup` panics on a fresh clone, the docs-only detector skips the tests that pin AGENTS.md and CHANGELOG.md, the Linux release runner floats, the updater signing key is in the environment of the whole build, six declared dependencies are unused with no gate, and the webview CSP and plugin capabilities grant more than the frontend uses. Documentation is rich and mostly accurate, but two architecture-doc rationales contradict AGENTS.md and the code, the operator RBAC role and README omit shipped features, five docs carry stale module paths, and the SSO wizard hardcodes the commercial cloud despite a sovereign-cloud abstraction. The product surface is unusually complete for its niche; the real gaps are Entra's 30-day soft delete being neither surfaced nor acknowledged, workload-identity Conditional Access, and tenant app-management policies.

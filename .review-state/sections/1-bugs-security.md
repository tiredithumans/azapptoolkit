## Bugs and security

This bucket holds the 113 verified defects and security findings from the review: 12 high, 58 medium and 43 low (92 tagged bug, 21 tagged security). Nine pairs or triples were reported independently at the same file and are merged below, so the section carries 103 entries; a merged entry names its other ids on the verdict line. Sub-themes are ordered by operator impact: wrong audit results first, then tenant mutations with the wrong outcome, backup and restore, auth and session, configuration, security hardening, caches, robustness, and finally tooling. Within each sub-theme entries run high, medium, low. Twenty-six findings carry a "partially" verdict; each entry states what the verifier corrected.

### Audit scoring and coverage accuracy

#### F151 · high · effort S · Mailbox advisory's name-shaped fallback misses MailboxItem.*/MailboxFolder.*/Mail-Advanced.*: org-wide read/write of every mailbox item scores as all-clear
`crates/azapptoolkit-core/src/scoping.rs:195` · confirmed, re-verified · also reported as F251 (`scoping.rs:75`, partially: the `graph_mail_role` omission is documented in exchange-scoping.md:46-50, but that rationale covers AAP-migration parity, not advisory membership)
**Problem.** `mailbox_named` tests only the prefixes `Mail.`, `MailboxSettings.`, `Calendars.` and `Contacts.`, so `MailboxItem.*`, `MailboxFolder.*` and `Mail-Advanced.*` never satisfy `is_mailbox_reaching_permission`. Microsoft's RBAC-for-Applications table lists all of them as Graph application permissions with scoped roles. An org-wide grant of `MailboxItem.ReadWrite.All` or `Mail-Advanced.ReadWrite.All` therefore yields no mailbox finding, no high-risk points and no Scope fix; the app ranks healthy. `HIGH_RISK_APP_PERMISSIONS` lists none of them either.
```
fn mailbox_named(value: &str) -> bool {
    ["Mail.", "MailboxSettings.", "Calendars.", "Contacts."]
```
**Proposal.** Extend `mailbox_named` with `MailboxFolder.`, `MailboxItem.`, `MailboxConfigItem.` and `Mail-Advanced.` and add a table test over Microsoft's supported-roles list; add the write/export variants to HIGH_RISK and the read variants to MEDIUM. Either add them to `graph_mail_role` with the CHANGELOG note exchange-scoping.md requires, or reword the UNCONFINABLE_MAILBOX recommendation, which currently claims RBAC has no role for them.
